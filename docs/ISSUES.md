## BM. 分钟是最小记录单位

| BM1 | 不变量 | 本应用的最小时间单位是**分**。计时器运行时可以走秒（它要显示秒），但任何被记录下来的时刻——记录的起止、计划的钟点——都只保留到它落在的那一分钟，秒一律归零。落地为 `Instant.wholeMinute()`（`truncatedTo(MINUTES)`）与 `LocalTime.wholeMinute()`，注释写明这是规则唯一的所在地，调用方不得自行取整。 |

| CB1 | 格式 | `data/backup/BackupFormat.kt`：一份 JSON 装下 8 张业务表（categories / plans / records / reminders / goals / property_definitions / property_values / plan_property_values），带 `app` + `format` 头，`schema` 只作诊断（映射按字段名，跨 schema 版本仍可读）。时间存 epoch 毫秒、日期存 epochDay、钟点存 secondOfDay（与 Room 转换器一致），枚举存名字。运行中的计时器与分片**不进备份**：那是进行中的会话，不是已存数据。 |
| CB2 | 恢复的原子性 | `BackupRepository.restore` 在**一个事务**里清空再写入，任何一步失败整体回滚，绝不会留下写了一半的库。清空顺序按外键：先 `timer_sessions`/`timer_slices`（运行中的会话指向分类与计划）、再子表到父表；分类表**自身**有外键，所以先删有父的、再删根（应用到今天为一层）。写入时反过来，分类按「父已写入」循环推进，父缺失的行降级为根而不是丢弃。 |
| CB3 | 本地导出/导入 | 走系统文件选择器（SAF `CreateDocument`/`OpenDocument`），不需要任何存储权限，文件归用户所有。导出文件名 `chronota-<时间>.json`；导入先弹确认框（会覆盖全部数据、不可撤销）再读文件。 |
| CB4 | WebDAV | `WebDavClient` 只用 `HttpURLConnection` 实现 PUT / GET / MKCOL（+PROPFIND 探活）与 Basic 认证——**没有新增任何依赖**。错误归类为 未配置 / 地址 / 账号密码 / 无文件 / 服务器 / 网络 六种，逐一对应一条文案。云端只维护一个滚动文件 `chronota-latest.json`：账号是用户的、文件很小，堆一堆历史没有意义；要历史就用本地导出。 |
| CB5 | 自动备份 | 复用应用已有的 AlarmManager + BroadcastReceiver 路子（`:app` 新增 `BackupReceiver`，含 BOOT/TIME_SET/TIMEZONE 重排）：按用户设定的钟点每天一次，`nextTrigger` 为纯函数（今天还没到就今天，否则明天），跑完自动排下一次；不需要新依赖、不需要 WorkManager。跑完（成功或失败）都记下时间与结果，设置页显示「上次备份 · 时间」或「尚未备份」。 |
| CB6 | 凭据与安全 | WebDAV 账号密码存 DataStore（应用私有目录）；`allowBackup=false` 且 `data_extraction_rules` 全面排除，所以不会被系统云备份带走。密码输入框已加遮挡。建议用网盘提供的**应用专用密码**而不是主密码。 |
| CB7 | 版本 | `versionCode 36` / `versionName 0.10.0`（M12 的备份部分落地）。 |
